# 🛡️ KernelCage: Hardware-Enforced AI Multi-Agent Orchestration

**KernelCage** is a high-performance, "bare-metal" orchestration framework for autonomous AI agents. Unlike standard frameworks that rely on software wrappers or heavy Docker containers, KernelCage leverages the **Linux Kernel** and **Access Control Lists (ACLs)** to physically enforce agent boundaries.

It treats AI agents as untrusted system services, ensuring they cannot "cheat," overreach, or modify protected files, even if their internal reasoning attempts to do so.

---

## 🚀 The Core Philosophy: "Hardware Over Hype"

Most AI agents "cheat" by looking at implementation details while writing tests or reading test cases while writing code. Software-based guardrails can be bypassed by a persistent LLM.

**KernelCage** solves this by:
1.  **OS-Level Isolation:** Running agents under a restricted, non-sudoer system user (`gemini-agent`).
2.  **Temporal ACLs:** Dynamically toggling filesystem permissions (`---`, `rx`, `rwx`) using `setfacl` in real-time.
3.  **Zero Overhead:** No Docker, no VMs, no synchronization lag. The agent and developer work on the **exact same files** with microsecond permission flips.

## 🛠️ Prerequisites

Before running the orchestrator, your system must be configured to support the "Cage" model:

1.  **Operating System:** Linux (Debian/Ubuntu/Fedora/Arch).
2.  **ACL Package:** 
    ```bash
    sudo apt install acl  # Debian/Ubuntu
    sudo dnf install acl  # Fedora
    ```
3.  **Dedicated Agent User:**
    ```bash
    sudo useradd -m gemini-agent
    # Ensure gemini-agent is NOT in the sudoers file.
    ```
4.  **Gemini CLI:** Installed at `/usr/local/nodejs/bin/gemini`.
5.  **Authentication Sync:**
    The `gemini-agent` needs its own authenticated session. Copy your existing credentials:
    ```bash
    sudo cp -r ~/.gemini /home/gemini-agent/
    sudo chown -R gemini-agent:gemini-agent /home/gemini-agent/.gemini
    ```

## 🏗️ The Architecture

The system operates in a **Research -> Strategy -> Execution** loop across three distinct agents. This repository includes a **To-Do List Application** being actively developed as a live demonstration of this framework; every line of code in the app is generated by the Gemini CLI under the strict physical boundaries of these agents.

### Agent Permissions Matrix

| Agent | `src/` | `tests/` | `TASKS.md` | `REVIEW.md` | `run.py` |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Developer** | **R+W** | None | R | R | None |
| **Tester** | None | **R+W** | R | R | None |
| **Reviewer** | R | R | **R+W** | **R+W** | None |

*   **R**: Read-only access
*   **W**: Write-only access (rarely used alone)
*   **R+W**: Full Read and Write access
*   **None**: Physically blinded to the file/folder via ACLs `---`

## 📝 The `run.py` Logic

The orchestrator manages the lifecycle by executing these core functions:

### 1. Permission Management (The "Cage")
```python
def mark_no_access(folder):
    # Physically blinds the gemini-agent to this folder.
    os.system(f"setfacl -R -m u:gemini-agent:--- {folder}")

def mark_read_only(folder):
    # Allows gemini-agent to read, but never modify.
    os.system(f"setfacl -R -m u:gemini-agent:rx {folder}")

def mark_write_access(folder):
    # Grants full autonomous control to the agent.
    os.system(f"setfacl -R -m u:gemini-agent:rwx {folder}")
```

### 2. The Orchestration Loop
The script iterates through the development lifecycle. In each step:
1.  Permissions are flipped for the specific agent.
2.  The `gemini-agent` user is invoked via `sudo -u`.
3.  The agent receives its prompt and performs its task.
4.  Permissions are reset before the next agent begins.

---

## 🛡️ Security Model: Why This Is Unbreakable

1.  **No Sudo for Agents:** If an agent attempts to fix a "Permission Denied" error by running `sudo`, the OS Kernel rejects it instantly.
2.  **Real-Time Watchers:** Because this is native, your VS Code or IDE will show you the agent's work as it happens, but you (the owner) always retain access to the files.
3.  **Kernel Enforcement:** Even a "rogue" AI cannot bypass `setfacl`. The permissions are checked at the hardware/kernel level for every file operation.

## 📂 Installation & Usage

1.  Clone this repository into your project root.
2.  Ensure your `TASKS.md` is populated with checkboxes (`- [ ]`).
3.  Run the orchestrator:
    ```bash
    python3 run.py
    ```

### Handling Crashes
If the script is interrupted, your files might remain in a "locked" state for the agent. To restore full access to your own user:
```bash
sudo chown -R your-username:your-username .
sudo chmod -R 777 .
```
